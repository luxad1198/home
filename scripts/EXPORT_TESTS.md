# Адресные проверки экспорта Word и PDF

**Запускайте только затронутый формат и нужную компанию.** Эти проверки не входят в обычные 12 smoke-тестов и не выполняются после каждой правки. Работайте с файлами **рабочей ветки**, без публикации тестовой версии сайта. При изменении общих данных/разметки обоих экспортов проверяйте оба формата.

| Изменение | Проверка |
| --- | --- |
| Исправили только Word-экспорт | `word` для затронутой компании |
| Исправили только CSS печати или PDF | `pdf` для затронутой компании |
| Исправили таблицу или условия, используемые обоими экспортами | `word` + `pdf` для затронутой компании |
| Затронули общие расчёты или все шапки | Все три компании в соответствующих форматах |
| Только интерфейс/калькулятор, экспорт не затронут | Экспортные проверки не требуются |

## 1. Word: создание настоящего DOCX и структурная проверка

В корне репозитория при наличии Node.js и Python 3:

```bash
npm install --no-save --package-lock=false playwright@1.56.1 docx@8.5.0 jszip@3.10.1 file-saver@2.0.5
npx playwright install chromium
node scripts/generate-word-documents.cjs ip-glazyrin
python3 scripts/check-word-documents.py ip-glazyrin
```

Вместо `ip-glazyrin` разрешены `ooo`, `ip` и `long` (длинный документ ООО). Без аргументов создаются и проверяются **все четыре** документа.

Playwright нажимает **существующую кнопку «Скачать Word»**, получает фактический скачанный DOCX и сохраняет его в `artifacts/word-docx/`. Библиотеки экспорта берутся из локального `node_modules` в закреплённых версиях, без CDN в тестовом браузере. Реальные пользовательские данные не используются.

Python проверяет, что DOCX — исправный OOXML ZIP, содержит тестовое оборудование, цены/итог, нужную налоговую формулировку, условия, подпись, таблицу спецификации, размер листа A4, поля и нижний колонтитул. Это **проверка содержимого и структуры**, а не визуальной верстки.

### Визуальная проверка Word (только при риске переноса/разрывов)

Если установлен LibreOffice и `pypdf`:

```bash
python3 scripts/render-word-documents.py ip-glazyrin
```

Она сохраняет `artifacts/word-rendered/glazyrin.pdf`, проверяет A4, наличие текста и минимум две страницы для случая `long`. PDF затем **нужно открыть и визуально проверить** — автоанализ не обнаружит каждое наложение/некрасивый перенос. LibreOffice может отличаться от Microsoft Word по шрифтам и пагинации, поэтому PDF от LibreOffice — ориентир, не доказательство идентичности Word.

## 2. PDF: печать через Chromium

Поднимите временный сервер в корне репозитория:

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

В другом терминале, если Playwright и `pypdf` установлены:

```bash
node scripts/generate-print-pdfs.cjs ip-glazyrin
python3 scripts/check-print-pdfs.py ip-glazyrin
```

Без аргументов генерируются/проверяются все четыре PDF. Результат — `artifacts/print-pdf/`. Проверяются A4, минимум страниц, тестовое оборудование, **сумма, НДС и подпись**. Для проверки переноса и внешнего вида нужно визуально открыть PDF. Ни один сценарий не открывает системное окно печати.

## 3. Дополнительная сверка Word и PDF (только если затронуты оба экспорта)

Оба генератора используют **одинаковые тестовые реквизиты, номер КП, оборудование, условия и суммы**, поэтому при изменении общей логики полезно проверить их согласованность:

```bash
python3 scripts/check-export-parity.py ip-glazyrin
```

Для сравнения нужны уже созданные `artifacts/word-docx/glazyrin.docx` и `artifacts/print-pdf/glazyrin.pdf`, а также Python-библиотека `pypdf`. Без аргументов сверяются все четыре сценария. Скрипт проверяет **наличие одинаковых ключевых данных в двух форматах**, не пиксельное сходство. Это **не обязательный шаг** после изменения только Word или только PDF.

## 4. Резервный путь: ручной GitHub Actions

Когда рабочая среда не позволяет запускать Chromium/Playwright, можно вручную проверить ветку PR:

- [Actions → Verify Word DOCX](https://github.com/luxad1198/home/actions/workflows/verify-word.yml): выбрать `Use workflow from` (ветку PR), `scope` (компанию) и при необходимости `render_layout` для LibreOffice. Скачать архив `word-export`.
- [Actions → Verify print PDF](https://github.com/luxad1198/home/actions/workflows/verify-print-pdf.yml): выбрать ветку и `scope`, скачать `print-pdf`.

Оба workflow **только ручные**, не запускаются автоматически на каждый PR. Выбирать `main` нельзя, если нужно проверить неслитые изменения. Артефакты хранятся 14 дней. Не объявляйте тест выполненным, если не получили его результат.

## 5. Ограничения

- Word-структура и PDF-содержимое проверяются независимо; дополнительная сверка сравнивает ключевые данные. **Пиксельное равенство Word и PDF не обещается**; даже число страниц может отличаться.
- Для экспорта Word проверяется создание и чтение DOCX, **не импорт DOCX**: импорт — отдельная функциональность.
- При локальном дефекте используйте `ooo`/`ip`/`ip-glazyrin`/ `long`, а не весь пакет. Полный экспортный прогон — при общих изменениях или по запросу.
