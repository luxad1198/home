# Базовые проверки КП: минимальный объём по риску

Набор: `scripts/smoke-tests.cjs` (Node.js + Playwright/Chromium). **Это инструмент выборочной регрессии, не обязательный полный прогон при каждом PR.** Он открывает файлы текущей рабочей ветки на временном `127.0.0.1`, без тестового сайта и без доступа к пользовательскому `localStorage`.

## Правило для агента — от узкого к широкому

1. **Мелкое локальное исправление:** воспроизведи исходную ошибку и проверь исправленное поведение. Если подходящий автотест есть — запусти **один** тест или его минимальную группу. Не запускай весь набор ради формальности.
2. **Общая функция / несколько зависимостей:** проверь связанную группу (например, расчёт спецификации для трёх компаний) и непосредственно затронутые сценарии. Расширяй охват только если нашли регрессию, изменили общую логику или виден реальный риск.
3. **Большие изменения / несколько подсистем:** полный smoke-набор; импорт Word и визуальный PDF — отдельно, когда затронуты.
4. **Только документация и инструкции:** функциональные браузерные проверки обычно не нужны. Не повторяй те же проверки при неизменённом коде.

**Не классифицируй проверку только по изменённому файлу:** в `app.js` есть и калькулятор, и печать, а в `style.css` — стили документа и интерфейса. Выбирай тест по реально затронутому поведению.

## Установка и запуск

Из корня репозитория: Node.js 22+, Playwright 1.56.1, Chromium. Если уже установлены — не переустанавливай.

```bash
npm install --no-save --package-lock=false playwright@1.56.1
npx playwright install chromium
```

**Адресный запуск** одной группы (пример — калькулятор):

```bash
node --test --test-name-pattern='^calculator:' scripts/smoke-tests.cjs
```

**Полный smoke-набор** — только при необходимости:

```bash
node --test scripts/smoke-tests.cjs
```

Для конкретного сценария используй его уникальное имя в `--test-name-pattern`. В Node.js тесты с несовпадающими названиями **пропускаются**, а не выполняются. **Код завершения 0 не доказывает, что выбранный тест запустился:** после команды проверь имена фактически выполненных тестов и число `pass` (не меньше 1, `fail = 0`), а не только итоговый код. Если все сценарии пропущены, считай проверку **не выполненной** и исправь фильтр. Если правился `app.js`, дополнительно достаточно дешёвой проверки `node --check app.js`.

## Группы адресных автотестов

| Группа (`--test-name-pattern`) | Сценарии | Когда нужна |
| --- | --- | --- |
| `^ui:` | B01–B02 — загрузка, переключение компаний, шапки и подписи | Формы, переключение компании |
| `^spec:` | B03–B05 — сумма двух позиций 3 × 1 250,50 + 2 × 100,25 = 3 952,00 ₽, формулировка НДС по трём компаниям | Расчёт спецификации и отображение итогов |
| `^equipment:` | B06 — добавление, удаление и нумерация позиций | Таблица оборудования |
| `^validation:` | B07 — неверные количество/цена блокируют печать, исправление возвращает её | Проверки ввода и запуск печати |
| `^storage:` | B08 — компания, заказчик, позиция, цена и итог после перезагрузки | Сохранение и восстановление |
| `^calculator:` | B09–B12 — три налоговых режима, ошибочный ввод и итоговая цена | Калькулятор и его формулы |

Каждый тест создаёт чистый браузерный профиль. Внешние CDN блокируются: проверка обычной логики **не охватывает импорт или экспорт DOCX**. Печатный диалог перехватывается только в тесте.

## Специализированные проверки — только по необходимости

| Сценарий | Что делать |
| --- | --- |
| Импорт DOCX | `scripts/IMPORT_TESTS.md`: адресные `append`, `replace`, `cancel`, `invalid`, `undo` и необязательный `roundtrip` |
| Экспорт Word | `scripts/EXPORT_TESTS.md`: настоящий DOCX, XML/реквизиты/таблицы/A4; LibreOffice-рендер — только при риске вёрстки |
| Печать/вёрстка PDF | `scripts/EXPORT_TESTS.md`: PDF конкретной компании (сумма, НДС, подпись, A4); при риске вёрстки — многостраничность и визуальная проверка |
| Пользовательские условия | `scripts/EXPORT_TESTS.md`: выборочные `conditions-ooo` / `conditions-ip` / `conditions-ip-glazyrin`, включая добавление, удаление, сохранение, нумерацию, Word/PDF |

Smoke-набор **не заменяет визуальный просмотр Word/PDF**. Проверка отсутствия явного разрыва OOXML не гарантирует, что Word не перенесёт длинный текст автоматически: при изменении переноса проверяй нужное место на странице после рендера. В отчёте перечисли реально запущенные группы/тесты и результат; не называй пропущенные тесты пройденными. Если рабочая среда не позволяет запустить Playwright, сообщи об ограничении. Не расширяй проверку только потому, что один тест невозможно выполнить.
