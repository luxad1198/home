# Проверка печатных PDF без диалога печати

Отдельный тестовый сайт не создаётся: сценарий проверяет **выбранную ветку** локально на `127.0.0.1` внутри временного GitHub Actions runner. PDF-проверка **не запускается автоматически** при создании или обновлении Pull Request.

## Когда запускать

Запускай проверку при изменениях, которые могут повлиять на печатный документ: макет A4, стили печати, таблицы, переносы, суммы в КП, условия сделки и подготовка печатной версии. При правках калькулятора или интерфейса, не затрагивающих КП, проверка PDF обычно не требуется. Повторяй её после исправления обнаруженных ошибок печати, а не после каждого коммита.

## Ручной запуск на GitHub

1. Открой [Actions → Verify print PDF](https://github.com/luxad1198/home/actions/workflows/verify-print-pdf.yml).
2. Нажми **Run workflow**.
3. В меню **Use workflow from** выбери **рабочую ветку нужного PR** (например, `fix/table-wrapping`), **не `main`**.
4. Нажми **Run workflow** и открой появившийся запуск.
5. После завершения скачай в разделе **Artifacts** архив **print-pdf** и проверь визуально поля, таблицы, суммы, переносы, подписи и разрывы страниц.

Важное отличие: при ручном запуске результат находится прежде всего на странице **Actions → конкретный запуск**, а не обязательно во вкладке **Checks** Pull Request. Для повторной проверки обновлённого PR снова выбери его ветку и запусти workflow.

При наличии установленного и авторизованного GitHub CLI можно запустить проверку командой `gh workflow run verify-print-pdf.yml --ref ИМЯ_ВЕТКИ`. Подключение GitHub к Work само по себе **не гарантирует права или инструмент для отправки workflow_dispatch**. Если агент не может запустить workflow, он должен дать владельцу название ветки и эти шаги; не пытаться заменить проверку фиктивным отчётом.

Архив содержит четыре тестовых документа: `rtstandard.pdf`, `zakharov.pdf`, `glazyrin.pdf` и `rtstandard-multipage.pdf` (проверка нескольких страниц). Данные вымышленные, артефакты хранятся 14 дней.

## Локальный запуск (Node.js, Python 3, Chromium Playwright)

```bash
npm install --no-save --package-lock=false playwright@1.56.1
npx playwright install chromium
python3 -m http.server 8765 --bind 127.0.0.1
```

В другом терминале:

```bash
node scripts/generate-print-pdfs.cjs
python3 -m venv .pdf-test-venv
.pdf-test-venv/bin/pip install pypdf==6.1.1
.pdf-test-venv/bin/python scripts/check-print-pdfs.py
```

PDF сохраняются в `artifacts/print-pdf/`. На Windows путь к Python виртуального окружения — `.pdf-test-venv/Scripts/python.exe`.

### Что проверяется

- Реальная кнопка **PDF / Печать**: валидация, подготовка DOM и стили `@media print`/`@page`; системный `window.print()` перехватывается.
- Наличие PDF для трёх компаний и многостраничного сценария.
- Читаемость PDF, формат A4, количество страниц и тестовые данные в тексте.
- Корректность суммы заполненной формы до печати.

Автоматизированные проверки не гарантируют совпадение визуальной вёрстки с Word или с PDF другого браузера; для окончательной оценки открывай сами PDF.
