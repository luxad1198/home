# Проверка печатных PDF без системного диалога печати

**Основной способ: локальный Playwright в рабочей среде агента.** GitHub Actions — **запасной**, если локальный Chromium или Playwright недоступен либо генерация заблокирована. Отдельный тестовый сайт не нужен, `window.print()` при тестировании перехватывается.

Проверку запускают **по необходимости**: если изменились печатные стили, A4, таблицы, условия, суммы, переносы, подготовка печати или другие элементы КП. При правках калькулятора/обычного интерфейса без влияния на печать PDF-тест не нужен. Не запускай его после каждого коммита только ради формальности.

Для выбора одной компании вместо четырёх и для проверки Word см. `scripts/EXPORT_TESTS.md`.

## 1. Основной вариант — Playwright локально

Работай с **актуальной рабочей веткой** и её файлами. Если Node.js и Playwright/Chromium уже установлены, повторная установка не требуется. При необходимости:

```bash
npm install --no-save --package-lock=false playwright@1.56.1
npx playwright install chromium
```

Запусти локальный сервер из **корня репозитория**:

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

В другом терминале:

```bash
python3 -m venv .pdf-test-venv
.pdf-test-venv/bin/pip install pypdf==6.1.1
node scripts/generate-print-pdfs.cjs ooo && .pdf-test-venv/bin/python scripts/check-print-pdfs.py ooo
```

Если `pypdf` уже есть в доступном Python, используй его без создания нового окружения. На Windows путь к Python виртуального окружения — `.pdf-test-venv/Scripts/python.exe`.

Команда выше проверяет **только ООО**. Для другой компании замени `ooo` на `ip`, `ip-glazyrin` или `long`; вызов без аргументов осознанно проверяет все четыре. Связка `&&` запрещает запуск Python-валидатора после ошибки генерации. Готовые документы находятся в `artifacts/print-pdf/`; при риске вёрстки просмотри их визуально. **Не присылай PDF/архивы владельцу без запроса**; для визуального исправления достаточно наглядного изображения, если возможно. Не выдавай локальный путь за доступную ссылку.

## 2. Запасной вариант — GitHub Actions (только ручной запуск)

Если в среде агента недоступен Playwright/Chromium или тест блокируется техническим ограничением, **один раз** переходи к проверенному резервному способу. GitHub Actions выполняет те же сценарии в изолированном runner на `127.0.0.1` и сохраняет архив PDF. Автоматического запуска на PR **нет**.

1. Открой [Actions → Verify print PDF](https://github.com/luxad1198/home/actions/workflows/verify-print-pdf.yml).
2. Нажми **Run workflow**.
3. В **Use workflow from** выбери **ветку нужного PR**, а не `main`.
4. Запусти проверку и открой соответствующий запуск в Actions.
5. В разделе **Artifacts** скачай архив **print-pdf** и проверь файлы.

Если в рабочей среде доступен авторизованный GitHub CLI:

```bash
gh workflow run verify-print-pdf.yml --ref ИМЯ_ВЕТКИ
```

Само подключение GitHub к Work **не гарантирует** возможность отправить `workflow_dispatch`. Если инструмент недоступен — сообщи владельцу имя ветки и приведённые шаги. Не утверждай, что проверка запущена или пройдена, если этого не было. Результаты ручного запуска появляются в **Actions**, не обязательно в **Checks** PR.

## 3. Результаты проверки

При запуске без выбора сценария оба способа формируют четыре документа: `rtstandard.pdf`, `zakharov.pdf`, `glazyrin.pdf`, `rtstandard-multipage.pdf` (многостраничный пример). Используются вымышленные тестовые данные.

Сценарий нажимает реальную кнопку **PDF / Печать**, проверяет подготовку DOM, расчёт итогов, стили `@media print`/`@page` и формирует PDF Chromium без системного диалога. Проверка Python анализирует читаемость, формат A4, количество страниц и контрольный текст.

**Ограничение:** автоматизированные проверки не доказывают пиксельное совпадение с Word или PDF из другого браузера. Для визуальной оценки нужно открыть сами PDF. Артефакты GitHub Actions доступны 14 дней.
