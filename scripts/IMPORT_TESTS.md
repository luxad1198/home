# Адресные тесты импорта оборудования из DOCX

Этот сценарий **не входит** в 12 базовых smoke-тестов. Выполняется только при изменениях импорта Word, структуры таблицы оборудования либо при подозрении на потерю данных.

## Что проверяем

| Режим | Содержимое проверки |
| --- | --- |
| `append` | Существующая строка остаётся; две позиции из реального ZIP/DOCX добавляются, **все поля обеих позиций** (включая страну, описание и суммы строк) и общий итог корректны после обновления страницы |
| `replace` | Существующие позиции полностью заменены импортированными; итог и `localStorage` согласованы |
| `cancel` | Просмотр DOCX без применения не меняет таблицу и финансовый итог |
| `invalid` | Повреждённый ZIP, документ без спецификации, неверное количество и цена **во второй позиции после корректной первой** отклоняются; применение заблокировано, прежние данные сохраняются **включая после перезагрузки** |
| `undo` | Отказ от подтверждения отмены сохраняет импорт, согласие возвращает прежнюю таблицу со **всеми описаниями, странами, ценами** и итогом |
| `roundtrip` | **Дополнительный** сценарий: экспорт настоящего Word из сайта → изменение таблицы → импорт этого же DOCX с заменой → сравнение результата |

Все тесты используют чистый профиль Chromium, фиктивные названия и временный локальный сервер. DOCX-файлы для основных проверок генерируются в памяти через JSZip: это полноценный OOXML ZIP с `word/document.xml`, без пользовательских данных. `roundtrip` вместо этого использует документ, действительно созданный кнопкой «Скачать Word».

## Команды (Node.js 22+, Chromium)

```bash
npm install --no-save --package-lock=false playwright@1.56.1 docx@8.5.0 jszip@3.10.1 file-saver@2.0.5
npx playwright install chromium

# Только исправленный участок импорта:
node scripts/import-docx-tests.cjs replace

# Все пять основных проверок импорта:
node scripts/import-docx-tests.cjs

# Отдельно проверка совместимости с экспортом нашего приложения:
node scripts/import-docx-tests.cjs roundtrip
```

Можно передавать несколько названий через пробел. При запуске без параметров проверяются **пять** основных сценариев; `roundtrip` остаётся необязательным. После запуска проверьте **не только код возврата**, но и счётчик выполненных тестов (`pass > 0`, `fail = 0`) и имена сценариев.

Проверки намеренно не изменяют общий экспорт Word/PDF и не требуют постоянного GitHub Actions. Когда локальный Chromium недоступен, разовый запуск на ветке PR допустим для верификации, после чего временный workflow удаляется. Не присылать владельцу DOCX/архивы без запроса.

**Границы:** синтетические документы подтверждают корректность парсинга известных столбцов, но не охватывают все шаблоны сторонних поставщиков; при жалобе на конкретный файл необходимо отдельно проверить этот файл с согласия владельца.
